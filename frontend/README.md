# NextTrack frontend

The public recommendation page is served at `/` by Django. It uses
dependency-free JavaScript modules and the existing `/api/v1/` endpoints;
there is no separate frontend development server. The public, read-only
Analytics page at `/analytics/` displays a compact snapshot of the verified V2
offline experiments, four evidence-backed findings, and the retained settings.
The page does not run a live comparison or expose raw recommendation runs.
Neither page exposes staff actions.
The Soft Indigo layout places controls, recommendation cards, and the selected
reason side by side on wide screens. It reduces to two and then one column as
the viewport narrows. The decorative record animation respects the user's
reduced-motion preference; it is not a server health check.

## Run locally

From the `NextTrack` directory in PowerShell:

```powershell
.\.venv\Scripts\python.exe backend\manage.py migrate
.\.venv\Scripts\python.exe backend\manage.py catalogue_status
.\.venv\Scripts\python.exe backend\manage.py runserver
```

Open `http://127.0.0.1:8000/`. The active catalogue must already be imported
for search and recommendation to work. The page and API share an origin, so no
development CORS configuration is necessary. The page keeps history only in
browser memory and sends it with each stateless recommendation request. A page
refresh clears the selection.

Search by title or artist and add up to five tracks. History order is oldest
to newest; the up/down controls change recency. Mood and BPM are optional.
The visible variety slider covers `0.0` to `0.4`, the reviewed experiment
range. Its displayed value is an MMR balance coefficient, not a measured
percentage of diverse tracks. Auto is the default; expand **Advanced algorithm
options** to select Basic CBF or Context + MMR. Auto on the page needs a history
track or a mood. **Surprise me** is a separate Random action that generates the
selected 5-, 10-, or 20-track list, respects BPM, excludes chosen history tracks,
and ignores mood and variety. The backend's Auto fallback remains unchanged
for API compatibility. Basic CBF needs history and ignores mood and variety.
Context + MMR needs history or mood. The results show relevance separately from
MMR selection evidence; Random has no numeric relevance score.
Relevance and MMR values display four decimal places, matching the public API
score precision. A 20-track response is shown in two client-side pages of ten;
all 20 are still ranked and returned by one request. This pagination reduces
on-screen clutter, not backend scoring work or response size. The frozen
offline Analytics studies remain Top-10 and are not regenerated by this change.
The listening-trail panel also offers a one-track suggestion form. It sends a
track name, artist name, optional album name, and optional supporting link to
the existing public review queue.
Superusers review suggestions at `/admin/`; submission or review does not add
the track to the active catalogue. Live API docs are not linked from the public
pages and require a superuser session after logging in at `/admin/`.
Long catalogue titles are truncated inside recommendation cards instead of
expanding the list over the adjacent reason panel. Ten results make the page
taller than five results; they do not change the card width or ranking rules.

For a manual browser check, search for a known artist, add a track, select a
mood, and generate five recommendations. Open the first result's reason panel;
then change the variety slider and generate again to inspect any rank changes.
Also try Surprise me with no history, Basic CBF with one history track, an invalid
BPM pair, and a narrow BPM range that yields no candidates. Check the layout
at desktop and narrow mobile widths. Headless screenshots were inspected at
1440 px and 500 px window widths. Narrower phone emulation and interactive
browser flows remain manual QA items.
For the long-title layout regression, leave history empty, choose Sad, and
request 10 and 20 tracks. Confirm that every card, including the long-title
track around rank 10, stays in the left column without covering the reason
panel; the 20-track list should switch between two pages of ten.

## Checks

```powershell
node --test frontend\tests\*.test.js
.\.venv\Scripts\python.exe backend\manage.py test `
  recommendations.tests.test_frontend_page `
  recommendations.tests.test_analytics_page
.\.venv\Scripts\python.exe backend\manage.py check
```

`frontend/base.html` contains the header, footer, metadata, and shared
stylesheet used by both pages. `frontend/index.html` contains the Discover page
content, while `frontend/analytics.html` contains the read-only experiment
page.

Static files are grouped by responsibility:

```text
frontend/static/frontend/
├── css/
│   ├── base.css
│   ├── discover.css
│   └── analytics.css
├── js/
│   ├── api.js
│   ├── model.js
│   ├── discover/
│   │   ├── dom.js
│   │   ├── history.js
│   │   ├── main.js
│   │   ├── results.js
│   │   ├── search.js
│   │   └── suggestions.js
│   └── analytics/
│       └── analytics.js
└── analytics/
    ├── snapshot.json
    └── figures/
```

`api.js` owns HTTP requests, and `model.js` contains request validation and
display helpers that can be tested without the DOM. `discover/main.js` owns the
page state and connects the smaller Discover modules. Analytics data and SVGs
remain outside `js/` because they are published experiment assets rather than
executable source files. The production deployment must run `collectstatic` and
serve `backend/staticfiles/` at `/static/` with a reverse proxy or static-file
service. Django's development server handles static files locally.

## Frozen Analytics snapshot

The snapshot is derived from `evaluation/v2`, including the catalogue audit,
configuration study, four-path comparison, performance study, and five figure
artifacts. It has no browser-side metric recalculation. Publish the verified
snapshot and figures from the project root:

```powershell
.\.venv\Scripts\python.exe backend\manage.py publish_analytics_snapshot `
  --input-dir evaluation\v2
```

The publisher verifies the experiment and figure manifests before replacing
the frontend snapshot and figure copies. A mismatch fails rather than silently
publishing changed evidence. The page gives the study scope and limitations,
including 12 synthetic scenarios, a fixed 500-track pool, incomplete artist
metadata, and local SQLite service timing.
